# Schema 生命周期（最小集）— 规格

## 1. 信息

- 规格 ID：SI-SCHEMA
- 状态：Draft
- 阶段：Phase 1 最小集（支撑「按 Schema 创建新图」）
- 依赖：[总体规格](README.md)

## 2. 用户故事

- 模型人员可以定义点类型、边类型与属性，保存草稿并发布版本。  
- 数据人员在建图时只能选择 **已发布** 版本，避免导入过程中模型被改乱。

## 3. 功能需求

### SI-SCHEMA-001 Schema 定义（P0）

- 平台保存 `schema_definition`：id、名称、描述、当前草稿、状态。  
- 草稿内容包含 Tag 列表与 Edge 列表（名称、属性名与类型、边的起止 Tag、主键/VID 策略说明）。

### SI-SCHEMA-002 草稿编辑与校验（P0）

发布前校验至少包括：

- Tag/Edge 名称合法且唯一。  
- 点具备约定的主键/VID 策略说明。  
- 边的起点、终点 Tag 存在。  
- 属性类型为平台支持集合（与 Nebula 类型映射表一致）。

验收：校验失败不可发布。

### SI-SCHEMA-003 发布不可变版本（P0）

- 发布生成 `schema_version`：递增版本号、完整快照、发布时间、发布人。  
- 已发布版本不可修改；变更须新草稿再发新版本。  
- 破坏性变更（删字段、改类型、改边端点等）须标为新主版本或显式「破坏性」标记（与 `schema-and-ingestion-design.md` 一致）。

### SI-SCHEMA-004 仅已发布版本可建图（P0）

- 创建图 / 映射 API 拒绝 `draft` 或未知 `versionId`。  
- 列表接口区分：建模用「草稿+版本」；导入建图用「仅已发布版本」。

### SI-SCHEMA-005 应用到 Nebula（P0）

- 由后端根据版本快照生成 DDL，在 **目标新建 Space** 上执行。  
- 禁止前端拼 DDL 直打图库。  
- 同一版本可应用到多个 Space（多次建图）。

### SI-SCHEMA-006 与静态 schema.ngql 关系（P1）

- 现有仓库根下 `backend/schema.ngql` 可作为内置种子模板导入为第一个草稿/版本。  
- 长期以平台元数据版本为准，文件仅作引导或导出。

## 4. 非目标

- 完整可视化建模 UX 的全部交互细节（可沿用模型构建页，但元数据须上后端）。  
- 跨版本自动数据迁移。  
- 自定义任意 Nebula 类型扩展而无映射表。

## 5. 验收场景

1. 创建草稿 → 校验失败（缺边端点）→ 修复 → 发布 v1。  
2. 建图下拉只见 v1，不见草稿。  
3. 再改草稿发布 v2 后，旧映射/旧图仍绑定 v1。
