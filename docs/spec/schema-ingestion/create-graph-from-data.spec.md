# 从已有数据按 Schema 创建新图 — 规格

## 1. 信息

- 规格 ID：SI-CREATE
- 状态：Draft
- 阶段：Phase 1 MVP
- 依赖：[总体规格](README.md)、[Schema 生命周期最小集](schema-lifecycle.spec.md)、[图空间选择](../graph-space/selection.spec.md)

## 2. 用户故事

- 作为分析/数据人员，我已有一批业务图相关数据，希望选定已发布的 Schema，映射后 **生成一张新图**，再在探索分析里使用。  
- 作为模型人员，我希望同一套 Schema 版本能被多次建图复用（正式图、演练图、压测图）。  
- 作为平台，我必须保证：建图时应用的 Schema 与映射钉死的版本一致，且浏览器不持有 Nebula 管理凭证。

## 3. 主路径（P0）

```text
选择已发布 Schema 版本
    → 选择/上传已有数据
    → 配置点边映射（VID、属性、边端点）
    → 抽样预检
    → 确认「创建新图」
    → 后端：CREATE SPACE → 应用 Schema DDL → 批量写入
    → 登记 GraphInstance（status=ready|failed）
    → 出现在可分析图目录
```

### SI-CREATE-001 创建意图（P0）

「创建新图」必须同时指定：

| 字段 | 说明 |
| --- | --- |
| `displayName` | 图的展示名 |
| `spaceName` | Nebula Space 名（合法字符集，全局唯一） |
| `schemaId` + `versionId` | 已发布版本，禁止 `latest` |
| 数据与映射 | 至少一个点类型映射；边映射可选但端点规则完整 |

验收：

- 缺任一必填项不得进入执行。  
- `spaceName` 已存在 → 拒绝创建（Phase 1 不做静默覆盖）；若需重跑，走「失败重试/明确重建」另议，默认禁止误覆盖。

### SI-CREATE-002 已有数据输入（P0）

Phase 1 MVP 至少支持一种「已有数据」形态（实现选定，规格要求可扩展）：

1. **文件**：CSV/JSON（点表、边表分文件或按约定多 sheet）；或  
2. **已登记数据源** 中的表/对象快照（若本期只做文件，须在非目标中写明）。

「已有图数据」在本规格中指：**业务侧已经存在的结构化点边数据**，不要求源系统本身是 Nebula。若源是另一 Nebula Space，Phase 1 可通过导出文件再导入，不强制 Space-to-Space 直连复制。

验收：

- 能预览样本行。  
- 明文密码不得进入前端存储或日志。

### SI-CREATE-003 映射（P0）

对每个目标 Tag / Edge Type：

- 点：源列 → VID；源列 → 属性；类型转换规则。  
- 边：源起点 VID、终点 VID、边类型、边属性；可选 rank。  
- 映射持久化时写入 `schemaId + versionId` 快照引用。

验收：

- 映射目标属性必须存在于钉死的 Schema 版本中。  
- 未知属性、类型不兼容在预检阶段失败。

### SI-CREATE-004 导入前门禁（P0）

执行建图前必须抽样或全量预检（MVP 可抽样 + 可配置阈值），至少包括：

- VID 非空、唯一（点）、符合 Space VID 策略。  
- 必填属性无空；类型可转换。  
- 边端点在点集合中存在，或声明「点边同批且点先边后」。  
- 错误率超过阈值 → 阻断创建。

验收：预检失败时不创建 Space（或创建失败后有明确回滚/标记，不得留下「ready 但空心」且可被分析误用的实例）。推荐：**预检通过前不 CREATE SPACE**。

### SI-CREATE-005 后端落地顺序（P0）

预检通过后，由后端原子业务事务（逻辑事务，非跨 Nebula+SQLite 真分布式 XA）执行：

1. 元数据落「建图任务 / graph_instance=creating」。  
2. `CREATE SPACE`（分区等策略用平台默认或请求参数）。  
3. 按 Schema 版本生成并执行 DDL（Tag/Edge/Index），等待就绪。  
4. 按映射批量写入点，再写边。  
5. 对账：写入行数 vs 源计数；抽样 `FETCH`。  
6. 成功：`graph_instance.status=ready`，登记进可查询目录。  
7. 任一步失败：`status=failed`，记录错误；Space 若已创建须标记不可用或执行约定清理策略（Phase 1 至少不可进入 ready 目录）。

验收：

- 浏览器网络面板无 Nebula 账号密码。  
- 失败不得返回 Mock 成功图。

### SI-CREATE-006 与探索分析闭环（P0）

图实例 `ready` 后：

- 出现在 `GET /api/v1/graph/spaces`（或等价图实例目录）中；  
- 用户可切换该 `space` 并点查导入的 VID。  

Phase 1 若仍部分依赖 `NEBULA_EXTRA_SPACES`，则建图成功 API **必须**同步更新平台权威目录；仅改 env 不算完成主路径。推荐以 **平台元数据目录为权威**，环境变量白名单退化为运维兜底（与 graph-space 规格演进一致，本文要求创建路径写入平台目录）。

### SI-CREATE-007 幂等与重跑（P1）

- 同一 `spaceName` 创建成功后禁止重复创建。  
- 同一导入任务失败后允许「修复映射后重跑」：行为须文档化（清空重写 vs 仅补失败批次）；MVP 可只支持「删失败实例后重建」。  

### SI-CREATE-008 权限（P0）

- 创建图 / 执行导入：需要既有或新增的写入类权限（如 `ingestion.write` / `schema.read`），与授权规格对齐。  
- 只读用户不可创建 Space 或触发 DDL。

### SI-CREATE-009 可观测性（P1）

- 任务进度：阶段（预检/建空间/DDL/写点/写边/对账）、百分比或行数。  
- 错误样本：行号、字段、原因（脱敏）。  
- 审计：谁、何时、哪个 schema 版本、哪个 space、结果。

## 4. 非目标

- 在已有 ready 图上原地改 Schema 并自动迁数（属迁移专题）。  
- 一次导入同时写入多个 Space。  
- 前端本地 `localStorage` 作为生产元数据真源。  
- 自动从任意 Nebula Space「反推」完整 Schema 再一键克隆（可作为后续「从已有图反演 Schema」专题）。

## 5. 验收场景

1. **主路径成功**  
   已发布 Schema + 合格 CSV → 创建新图 → 目录可见 → 点查命中。  

2. **预检阻断**  
   故意制造类型错误/空 VID → 不建 Space（或不出现 ready）。  

3. **版本钉死**  
   映射绑定 v1；即使后来发布 v2，本次任务仍按 v1 DDL/字段写入。  

4. **同 Schema 多图**  
   用同一 `versionId` 创建两个不同 `spaceName`，互不影响。  

5. **无 Mock 伪装**  
   Nebula 不可用时任务失败可见。  

## 6. 开放问题

1. Phase 1 已有数据是否只做 CSV/JSON 文件，还是必须含库表数据源？  
2. 建图失败后 Space 是自动 DROP 还是保留并标 `failed` 供排查？  
3. 图目录权威：仅平台元数据，还是元数据 ∪ env 白名单并集？  
4. 异步 Job：MVP 同步等待还是必须上队列（百万行必须异步）？

建议默认：

1. MVP 先文件（CSV/JSON），库表作 Phase 1.1。  
2. 失败默认保留 Space 并标 `failed`，提供「废弃/删除」操作。  
3. 平台元数据为权威；env 白名单仅运维兜底且文档声明。  
4. 小数据可同步；超过阈值（如 10 万行）强制异步任务。
