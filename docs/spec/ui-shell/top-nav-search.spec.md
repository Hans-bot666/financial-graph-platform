# 顶栏信息与场景搜索规格

## 1. 信息

- 规格 ID：UI-TOP-SEARCH
- 状态：Draft
- 更新时间：2026-09-14
- 适用范围：`TopNav`、`SideNav`、`MainLayout`、场景看板与子图本地数据

## 2. Why

当前顶栏同时展示连接状态、当前连接图空间、用户管理、用户名和退出，信息密度偏高，而且“当前连接图”会让用户误以为所有页面都锁定在该图空间。用户管理属于主功能入口，更适合放在左侧导航；用户名旁缺少角色信息，也无法快速判断当前权限身份。

场景与子图逐渐增多后，只靠场景看板逐页查找效率不足。顶栏需要一个全局搜索入口，允许用户搜索场景和子图，并保留最近搜索历史。

## 3. 目标

1. 顶栏保留数据库连接状态，但不再展示当前连接的图空间名称。
2. 用户管理从顶栏迁到侧边栏，并继续按 `user.read` 权限控制可见性。
3. 顶栏用户区展示当前用户角色。
4. 顶栏中间增加场景/子图搜索框，交互参考提供的搜索面板图片。
5. 搜索不改变现有场景、子图存储模型和页面业务逻辑。

## 4. 顶栏要求

### UI-TOP-001 隐藏当前图名（P0）

- 保留“已连接 / 未连接”状态点和文字。
- 删除状态右侧的 `space` 文本。
- 健康检查仍可返回 `space`，只是顶栏不显示；探索分析中的图空间选择不受影响。

### UI-TOP-002 用户角色（P0）

- 用户头像区域展示显示名/用户名，以及角色文案。
- 角色来自当前会话 `user.roles`，不能由前端自行推断权限。
- 内置角色显示名：
  - `platform_admin` → 平台管理员
  - `analyst` → 分析员
  - `viewer` → 查看者
- 多角色时按优先级显示主角色，可在 `title` 中显示全部角色；未知角色回退原始 code。
- 无角色时显示“未分配角色”。

## 5. 用户管理迁移

### UI-SIDEBAR-ADMIN-001 权限控制（P0）

- 从 `TopNav` 删除“用户管理”按钮。
- 在 `SideNav` 的业务菜单下方增加“用户管理”入口。
- 仅当 `hasPermission('user.read') === true` 时渲染。
- 不使用“用户名是不是 admin”或仅匹配角色名作为判断，后端权限仍是最终授权。
- 点击后切换主工作台 `admin` Tab，不再离开 `MainLayout`。
- 窄栏只显示用户管理图标；悬停展开后显示文字。
- 当前为用户管理时使用与其它模块相同的选中态。

## 6. 全局搜索

### UI-SEARCH-001 搜索范围（P0）

Phase 1 搜索当前 `board-store` 中的：

- 场景：`SceneBoard.name`、`description`
- 子图：`SubGraph.name`、`query_text`

本期数据源是浏览器本地存储；后续切到后端 Metadata API 时保持 UI 契约不变。

### UI-SEARCH-002 搜索框位置与状态（P0）

- 搜索框位于 `TopNav` 中部，左右分别保留面包屑和用户/连接状态。
- 搜索框左右两端使用完整圆角（胶囊形）。
- 未聚焦且无内容时收缩为圆形搜索按钮，只显示搜索图标。
- 点击/聚焦后以约 300ms 动画展开为中等宽度胶囊，并显示提示文案“搜索场景或子图”。
- 输入存在内容时，即使搜索面板暂时关闭，搜索框仍保持展开；清空且失焦/关闭后收缩。
- 展开/收缩动画需尊重 `prefers-reduced-motion`。
- 支持输入、清空按钮、`Escape` 关闭、点击外部关闭。
- 输入为空时展示搜索历史；有关键词时展示匹配结果。

### UI-SEARCH-003 搜索结果（P0）

每条结果必须包含：

- 左侧类型缩略图：
  - 场景：场景/看板图标和主题色背景
  - 子图：优先使用子图 `thumbnail`；没有缩略图时使用图网络占位图标
- 中间：名称；第二行显示“场景”或“子图 · 所属场景名”，可附描述/查询摘要。
- 右侧时间：
  - 优先显示 `updated_at`，文案“更新于 YYYY-MM-DD”
  - 若没有更新时间则显示 `created_at`，文案“创建于 YYYY-MM-DD”

结果排序：名称/描述命中后，按 `updated_at` 降序；结果数量设上限（建议 20）。

### UI-SEARCH-004 搜索历史（P0）

- 历史保存在独立 localStorage key，不能混入 board 数据。
- 记录用户成功打开过的结果（类型 + ID + 最近访问时间），最多保留 8 条，重复项置顶。
- 输入为空时显示“最近搜索”；不存在或已删除的对象自动过滤。
- 提供“清除历史”操作。
- 历史条目与普通结果使用相同的类型图标、名称和时间布局。

### UI-SEARCH-005 打开结果（P0）

- 点击场景结果：
  - 切换到 `home`（场景看板）。
  - 滚动到并短暂高亮目标场景卡片。
- 点击子图结果：
  - 沿用现有 `onNavigateToExplore(sceneBoardId, graphData)` 语义。
  - 进入探索分析并加载该子图。
- 打开成功后记录历史并关闭搜索面板。

### UI-SEARCH-006 空态与键盘（P1）

- 无结果显示“未找到相关场景或子图”，不伪造数据。
- 支持上下方向键移动结果焦点，Enter 打开选中项。
- 搜索框、关闭、清除历史和结果项具有可读 `aria-label`。

## 7. 非目标

- 本期不搜索图数据库中的顶点/边。
- 本期不搜索模型、数据源、特征或用户。
- 不把当前图空间选择迁到顶栏。
- 不新增后端全文检索接口。

## 8. 验收

1. 顶栏只显示连接状态，不显示 `anti_fraud_kg` 等当前图名。
2. 普通用户看不到用户管理；具备 `user.read` 权限的管理员可在侧边栏看到并进入。
3. 用户区显示“平台管理员 / 分析员 / 查看者”等角色。
4. 点击中间搜索框，空输入显示历史；输入关键词显示场景和子图。
5. 每条结果左侧能区分场景/子图，右侧显示创建或更新时间。
6. 点击场景定位场景卡，点击子图进入探索分析；历史随成功访问更新。

## 9. 已确定与实现默认

- 管理员可见性继续使用现有 `user.read` 权限。
- 搜索范围仅场景和子图。
- 搜索历史记录成功打开的结果，而不是保存任意未执行关键词。
- 时间优先使用更新时间。
