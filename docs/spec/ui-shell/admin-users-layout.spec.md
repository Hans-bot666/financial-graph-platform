# 用户管理并入主工作台规格

## 1. 信息

- 规格 ID：UI-ADMIN-LAYOUT
- 状态：Implemented
- 更新时间：2026-09-14
- 依赖：`MainLayout`、`SideNav`、`TopNav`、`TabKey`、`user.read`
- 不改：后台用户 API、RBAC、列表/对话框业务逻辑

## 2. Why

用户管理目前走独立路由 `/admin/users`，自带一套顶栏和返回按钮，离开了主工作台的侧栏 + 顶栏壳。管理员在「场景看板 / 模型构建 / 数据接入 / 探索分析 / 特征工厂」和用户管理之间切换时，导航、面包屑和退出入口都不一致。

用户管理与其它模块一样是登录后的工作台能力（仅权限更窄），应使用同一套 Layout，而不是另开管理后台壳。

## 3. 目标

1. 拥有 `user.read` 的用户从侧栏进入用户管理时，仍停留在 `MainLayout`。
2. 切换方式与其它模块相同：`onTabChange('admin')`。
3. 顶栏面包屑显示「用户管理」，搜索、连接状态、角色、退出保持不变。
4. 去掉用户管理页内部的平台 Logo 顶栏和「返回平台」按钮。
5. 无 `user.read` 的用户看不到入口，也无法通过旧 URL 进入该页内容。

## 4. 非目标

- 不改用户列表、创建、编辑、角色、启停、重置密码的 API 与对话框。
- 不把用户管理做成可给所有角色使用的业务模块。
- 本期不为五个业务模块补齐 URL Tab 同步；仅处理用户管理旧路径兼容。

## 5. How

### UI-ADMIN-001 Tab 模型（P0）

- `TabKey` 增加 `'admin'`。
- `MainLayout.renderPage()` 在 `activeTab === 'admin'` 时渲染现有 `AdminUsers`。
- 无 `user.read` 时不得停留在 `admin` Tab，回退到 `home`。
- `handleTabChange('admin')` 与切换到其它非探索页一样，清空探索跳转上下文。

### UI-ADMIN-002 侧栏入口（P0）

- 「用户管理」不再 `navigate('/admin/users')`。
- 点击调用 `onTabChange('admin')`。
- 仍仅在 `hasPermission('user.read')` 时渲染。
- 选中态与五个业务模块一致（蓝色背景 + `aria-current="page"`）。
- 位置保持在五个业务模块下方，视觉分组可保留间距，但交互必须是同一个导航列表语义。

### UI-ADMIN-003 页面壳（P0）

- 删除 `AdminUsers` 内部粘性顶栏（平台 Logo、独立「用户管理」标题、当前用户名）。
- 删除「返回平台」按钮。
- 页面作为 `MainLayout` 内容区滚动：`h-full overflow-auto`，不再 `min-h-screen` 自建整页背景。
- 保留内容区标题「用户管理」和说明文案、查询/筛选/表格/对话框。

### UI-ADMIN-004 筛选状态（P0）

- 用户管理嵌入根路由 `/` 后，筛选条件不得写入根 URL Query，避免污染场景看板地址。
- 查询词、状态、角色、分页改为组件内状态。
- 离开该 Tab 再进入时允许重置筛选（与其它模块卸载即重置一致）。

### UI-ADMIN-005 旧路径兼容（P0）

- `/admin/users` 不再渲染独立页面。
- 已登录且有 `user.read`：跳转到 `/` 并打开 `admin` Tab。
- 已登录但无 `user.read`：跳转到 `/403`。
- 未登录：仍由 `RouteGuard` 送到登录页。
- 后端 `/api/v1/admin/*` 路径不变。

### UI-ADMIN-006 顶栏（P0）

- `TAB_TITLE.admin = '用户管理'`。
- 用户管理 Tab 下仍显示全局搜索；搜索打开场景/子图的行为不变。

## 6. 验收

- 管理员点击侧栏「用户管理」，内容区切换到用户列表，左侧栏和顶栏仍在。
- 当前项有选中态，顶栏面包屑为「用户管理」。
- 可从用户管理再点「场景看板」等模块，无需「返回平台」。
- 分析员/查看者看不到该入口；直接访问 `/admin/users` 进入 403。
- 用户查询、分页、新建、编辑、角色、重置密码、启停仍可用。
