## 3. 为什么要做（Why）

### 3.1 现状问题

1. **前端“当前分析图”是假目录**  
   `ingestion-store` 硬编码仅返回 `对公贷款反欺诈图 / anti_fraud_kg`。百万图空间 `random_financial_graph_million` 已在 NebulaGraph 中存在，但 UI 下拉无法选到。

2. **后端查询绑定单一环境变量**  
   `NEBULA_SPACE` 在连接时固定 `USE`。即使前端改下拉文案，查询仍打到默认空间，切换没有真实效果。

3. **产品验收缺口**  
   企业级集成计划 Phase 1 验收明确要求：**用户可选择图空间**，再执行受控查询与场景。当前能力不满足该验收项。

4. **数据生成与分析脱节**  
   一万 / 百万随机图脚本可写入不同 Space，但分析工作台无法指向对应 Space，联调与压测价值被截断。

### 3.2 要解决的核心矛盾

> 图数据已是多空间，平台交互仍是单空间。

若不先打通「目录可见 + 请求可携带 + 服务端校验后 USE」，后续 Schema 发布、场景绑定、权限按空间隔离都会建立在错误假设上。

### 3.3 本期目标（What we want now）

1. 已登录用户能看到**平台允许的图空间列表**（不是前端写死）。
2. 探索分析页可切换当前图空间；切换后清空当前画布结果，避免跨空间误读。
3. 点查 / 展开 / 路径 / 场景执行等图查询请求携带目标空间标识，**后端校验后在该空间执行**。
4. 禁止任意字符串作为 Space 名直通 Nebula，防止误用或越权访问未登记空间。

### 3.4 本期不做（Non-goals）

- 租户 / 机构 / 部门级图空间数据隔离（仍属授权后续阶段）。
- 在线创建、删除、改名图空间或在线改 Schema。
- 全图精确 `COUNT` 统计作为列表必填字段（百万空间全表扫描成本过高）。
- 前端直连 NebulaGraph 或在浏览器持有图库凭证。

### 3.5 设计原则

| 原则 | 说明 |
| --- | --- |
| 后端为权威 | 可查询空间列表与最终 `USE` 目标由后端决定 |
| 显式携带 | 每次图分析请求声明 `space`，不依赖隐式全局单例 |
| 白名单 | 仅允许配置/登记过的 Space，拒绝未知名 |
| 渐进演进 | Phase 1 用配置目录即可；后续可迁到 SQLite 元数据表 |
| 与现有 UI 对齐 | 复用探索分析页「当前分析图」下拉，不新开平行入口 |

## 4. 目标

1. 提供图空间目录 API。
2. 探索分析页用真实目录驱动下拉与当前选择。
3. 图查询与场景执行按所选空间执行。
4. 错误可诊断：空间不存在、未授权（Phase 1 即未登记）、Nebula 不可用。

## 5. 范围

### Phase 1

- 后端维护可查询图空间目录（环境变量 / 配置文件白名单，含展示名、状态）。
- `GET` 目录接口；图查询请求体增加 `space`（或等价字段）。
- 探索分析：加载目录、切换、按空间发请求。
- 健康检查可回报当前默认空间，但不替代按请求选择。

### Phase 2（预留，本文不展开实现）

- SQLite / 元数据库持久化图空间目录、Schema 版本、导入任务关联。
- 按角色/用户授权可见空间集合。
- 可选的近似统计与「就绪」探测。

## 6. 总体架构

```text
React 探索分析
  ├─ 当前分析图下拉 ← GET /api/v1/graph/spaces
  ├─ 本地记住上次选择（可选）
  └─ lookup / expand / paths / scenarios 请求体携带 space
          │ 同源 / Cookie 会话
FastAPI
  ├─ Graph Space Catalog（白名单 + 展示元数据）
  ├─ 校验 space ∈ 目录且 status 可用
  └─ Nebula session：按请求 USE {space} 后执行受控 nGQL
          │
NebulaGraph
  ├─ anti_fraud_kg
  ├─ random_financial_graph_million
  └─ …（仅白名单内可见）
```

## 7. 与现有模块关系

| 模块 | 关系 |
| --- | --- |
| 认证 / RBAC | Phase 1 沿用现有登录与图查询权限；不做 per-space ACL |
| `ingestion-store` | 停止作为唯一真源；可保留本地导入任务态，但分析图列表改为 API |
| `NEBULA_SPACE` | 保留为**默认空间**（目录缺省、健康检查），不再是唯一可查询空间 |
| 随机图脚本 | 写入的 Space 需加入目录白名单后才能在前端选到 |

## 8. 成功标准（验收摘要）

1. 目录至少包含 `anti_fraud_kg` 与 `random_financial_graph_million`（在配置启用时）。
2. 切换到百万空间后，查询 `million_*` VID 有结果；切回 `anti_fraud_kg` 后同一查询不应误命中百万数据。
3. 请求未带 `space` 或带未登记 `space` 时，API 明确失败，不得静默落到默认空间（除非规格允许缺省并文档化）。
4. 浏览器网络面板中无 Nebula 账号密码。

详细需求与验收见 [selection.spec.md](selection.spec.md)。
