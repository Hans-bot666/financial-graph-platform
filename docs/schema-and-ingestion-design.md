# 图 Schema 与数据接入设计

## 使用逻辑

1. 在模型构建左侧创建或切换 Schema。
2. 在画布添加点类型并拖动布局；选中点后在右侧定义名称、标签说明、主键和属性类型。
3. 创建边类型，选择起点/终点类型并定义边属性。
4. 保存草稿可继续编辑；发布前校验点类型名称、唯一主键、边端点和属性定义。
5. 发布生成不可变版本，数据接入只展示已发布版本。
6. 数据接入选择数据源和点/边目标，配置 VID、起终点 VID 和属性字段映射。
7. 抽样预检类型、空值、重复主键、边端点引用和错误率，通过后才创建正式导入任务。

## 元数据边界

- `schema_definition`：Schema 身份、名称、状态和当前草稿。
- `schema_version`：不可变点边快照、版本号、兼容性结论和发布时间。
- `data_source`：连接类型、凭据引用、对象/表，不保存明文密码。
- `mapping_job`：固定绑定 Schema 与版本，包含点/边映射、转换和质量规则。
- `ingestion_run`：执行状态、行数、错误样本、重试批次和审计信息。

浏览器本地存储只用于当前 Demo 打通交互；生产环境必须由平台 API 写入元数据库。NebulaGraph DDL 和导入任务由后端根据已发布版本生成并审批执行，浏览器不直接访问数据库管理接口。

## 版本与兼容性

- 新增可空属性：通常向后兼容。
- 删除/重命名属性、修改类型、修改主键、改变边端点：破坏性变更，必须新建主版本并重新确认映射。
- 已发布版本不可覆盖；回滚的本质是从旧快照创建新草稿。
- 每个映射任务保存 `schema_id + version_id`，禁止引用“最新版本”这种漂移指针。

## 导入前门禁

- VID 非空、唯一且符合 Nebula Space VID 类型/长度。
- 点主键非空且重复率为零。
- 属性值可按目标类型转换；必填属性无空值。
- 边的起点/终点存在，或明确配置点边同批导入顺序。
- 抽样预检、错误阈值、幂等键、批次重跑和对账指标均已配置。
